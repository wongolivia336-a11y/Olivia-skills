# 稚拙风 PPT

## 先确认内容，再套用风格

- 阅读用户给的 PPT、截图、文档或链接。提取标题、表格、顺序和不可遗漏的信息。
- 沿用用户指定的页数、语言与交付格式。无指定时，默认交付连续 HTML；按内容决定页数，勿机械凑十页。
- 新任务使用新文件名；修改已有文件时保留身份与版本。用户要求独立任务时不要覆盖旧文件。
- 把这套规范作为视觉与表达方法，勿把“薛定谔的猫”、机器人或存在主义当作固定主题。

## 固定视觉

| 项目 | 默认值 |
| --- | --- |
| 页面 | 16:9，1280 × 720 |
| 背景 | 纯白 #FFFFFF，勿使用暖白、纸纹或渐变 |
| 插画、强调色 | 橘红 #E6532F；插画只用这一种颜色 |
| 正文 | 深灰 #252523；辅助文字 #74746D |
| 内边距 | 左右 76–80 px，上方 58–66 px |
| 英文标题 | 常用 48–58 px，封面 72–84 px；常规或中等字重 |
| 中文正文 | 常用 20–24 px；表格 18–20 px |
| 脚注 | 13–16 px，只放必要来源或假设说明 |

- 每页围绕一个问题或信息点。让留白来自删减和布局，不靠把字缩小。
- 使用平面排版：标题、文本列、轻表格、插画。避免卡片堆叠、粗分隔线、大色块、阴影和装饰图标。
- 默认英文主标题、中文解释。优先准确自然的英文，不为“高级感”生造词。
- 保持正文清晰整齐，插画故意笨拙。不要让文案、对齐或信息逻辑一起变乱。
- 根据内容选布局：封面左右构图；概念页一段话加插画；比较页平行列；流程页一图一步；精确映射使用可编辑表格。

## 文案尺度

阅读 [references/copy.md](references/copy.md) 后改写文案。

- 写得介于通俗和思辨之间：能在课堂上自然讲出，也留下讨论空间。
- 删除空泛套话、技术腔和廉价口号。使用具体动作、具体体验、明确问题。
- 不把内容压成“看不见。感觉得到。”这类碎句。短不等于有力。
- 区分已知事实、设计设想和待验证问题。勿把思辨借喻当成科学证明。
- 如涉及市场案例，查阅当前官方资料，保留可点击来源；不要编造功能、尺寸或效果。

## 稚拙插画

阅读 [references/illustration-prompts.md](references/illustration-prompts.md)，使用其中的生成或转绘模板。

- 用可用的图像生成工具制作新的位图插画；转绘时先查看参考图，再进行编辑或以参考图生成。
- 保留主体的辨识特征，允许比例歪、断线、重描、透视不准和像素阶梯。增加内容细节，不增加精致感。
- 持续使用橘红色和纯白背景。不要混入黑色、灰色阴影、其他彩色或专业矢量图风格。
- 给封面、物种/类型、案例、形态和交互流程配有意义的插画；无需每页都塞图。
- 精确图表、数据和科学机制保持确定性绘制。不要让生成图承担精确信息；图中标签交给 HTML 或幻灯片文字。
- 流程插画保持同一对象的外壳、窗口、视角与比例。保证每个图和对应文字一一对齐。

## HTML 交付

使用 [assets/starter.html](assets/starter.html) 作为起稿基础；替换占位内容，而不是交付模板。

- 每页一个固定尺寸 section，纵向连续排列；页面之间留 28 px。打印时每页单独分页。
- 保留可编辑文本和表格，提供打印按钮与复制完整 HTML 源码按钮。
- 所有插画嵌入为 data URL，或明确提供完整资源包；不要留下临时图片链接、绝对本地图片路径或依赖网络的字体。
- 保持图片宽高比。只裁去无用留白，不裁掉耳朵、手或主体。勿用 object-fit:fill 拉扁插画。
- HTML 本身不能直接粘贴成为 Figma 图层。用户需要时说明使用支持 HTML 导入的插件；直接写入 Figma 时遵循相应 Figma 技能。
- 用户要 PPTX 时，遵循演示文稿技能生成 PPTX，不把 HTML 当作已完成的 PPTX。

## 交付前检查

1. 核对页数、文字、表格与用户材料；确认独立文件没有覆盖之前的作品。
2. 核对纯白底、统一橘红插画、足够留白和自然语言。
3. 渲染每一页，检查文字换行、遮挡、越界、图文对齐和图像比例。
4. 测试资源嵌入、打印分页、复制按钮和本地打开。
5. 修复问题后交付；若渲染工具不可用，说明未完成视觉检查，不把结构检查说成视觉验证。
6. 按当前环境的持久化规则保存用户作品，返回完整 HTML 源码文件链接。
