# Learning Loop v0.1 | 可解释、可审查的个性化生长

目标不是猜测一个固定“用户画像”，而是在连续论文精读中**积累关于学法的可反驳假设**，并逐步提升问题质量。公开仓库只存通用教学机制与匿名示例；真实会话记录默认留在本地非跟踪目录，未经许可不写入 GitHub。

## 两层记忆
1. **Session notes**：单篇论文的阅读进度、误解、关键概念、方法缺口、用户提出的反例、下次入口；按 templates/session-note.md 记录。
2. **Reader profile**：跨多轮多篇论文稳定出现的解释方式偏好、适当难度、典型盲点及可用领域映射；位于 reader-profile.md，公开字段只有用户明确同意的非敏感抽象项。

不要存储心理诊断、身份、私人生活和未经公开的研究项目细节。保存前先删除可识别内容；上传公有仓库前再次审查。

## 观察 → 假设 → 试用 → 反馈 → 晋升
- Observe：捕捉明确陈述或重复出现的行为，如“先讲图，再讲定义”“我不希望每次都追问”“能否解释为什么这个指标有效”。
- Hypothesize：把观察写成待验证的教学假说；一轮回答只算 weak，不泛化为永久设定。
- Test：下一次同类任务适度尝试一种改变，清楚表明可随时取消。
- Feedback：用“是否更容易理解 / 是否帮助追问 / 有没有遗漏关键证据”等反馈评估；反例与负反馈同等重要。
- Promote：获得跨任务重复证据或用户明确认可，才**建议**修改公开 reader-profile.md；提供差异、原因与撤销方式，用户同意后通过 GitHub commit/PR 更新。

用户明确要求“更新我的阅读偏好”可以立即提出有据的变更，不要求机械攒到三次；但一条具体学术立场不应变成对人的永久标签。

## 每轮轻量学习反馈
在讲解结束时最多提出一个紧贴文章的思辨题。用户回应后：
- 标注用户已经掌握的区分；
- 指出一个尚未证明的逻辑跳跃（如把用户评价与系统授权混为同层级）；
- 将这个讨论生成可供下次复用的**通用案例**，不要偷换成论文作者的观点；
- 用户明显已经理解时推进到下一张图、实验或方法，不重复课堂答题。

## 复习节奏（不创建后台任务）
可选：“下次从这里继续”“明天复述机制”“一周后跨论文比较”。默认没有自动提醒、后台爬取或自发 PR。需要自动化时必须另行获得用户授权并配置实际运行机制。

## 记录与保护
脚本 scripts/log_reflection.py 只将用户批准的脱敏短观察写到本地 data/private/learning.jsonl；Git 明确忽略该路径。运行脚本不等于部署后台记忆系统。保存的记录可手动删除；公开 profile 变更由用户审查。

## 回归质量检查
- 讲解是否越来越贴近用户实际提问，还是陷入循环重复？
- 是否能明显区分作者、教学例子与用户的新假说？
- 是否给出原文页码而非幻觉式引文？
- 追问是否推进理论，还是把任何话题都引向 AI？
- 是否因为“个性化”缩窄未知领域的好奇心？
- 是否因一次回答就推断用户永久立场？
- 是否未经许可写入公开仓库或宣称后台会自动成长？

允许随时通过 Git 历史撤销公开更新；所有私有学习记录的清理在本地进行。
