# Editorial Data PPT

**设计减法，信息加法。** 源于一组生命感研究 PPT 的实际修改经验，以及对小红书营销／策略提案的高信息量编辑布局的借鉴。借鉴**方法与视觉组织**，不擅自再分发原营销方案、素材或文案。

## 什么时候用

- 把用户调研、案例库、标签框架、洞察转成正式答辩 PPT / Figma 信息图。
- 复刻已提供的参考图（明确要求1:1时）或将其**信息组织逻辑**移植到用户现有模板。
- 制作多维数据可视化、产品案例卡、设计机会、体验蓝图、后续概念设计语言。
- 用户明确调用 `$editorial-data-ppt`。

## 三种不同指令，不能混淆

**严格复刻**：用户要求“1:1、内容不改、只加不删”时，原文、顺序、形状、比例、颜色、底图及角标都是锁定项。逐层重建可编辑图层，不自行发挥。

**受控转译**：用户允许改图表/排版时，只转换表达形式，数据、结论、信息层级、既定视觉系统不变。先给旧→新映射，逐项自检。

**探索与新增**：另开新画板做备选分析，不覆盖旧版，不伪造数据，不把灵感稿说成定稿。

## 先研究，再设计

1. 读取 PPT、报告、Figma 节点、访谈、案例库及用户的修订反馈。只认定来源明确的内容。
2. 建事实表：原始案例编号、标准产品名、同产品合并关系、设备品类、唯一主类、辅助标签、五个二级分析轴、三级词条、评分、证据链接、缺失值。
3. 先核算**原记录数 vs 去重产品数 vs 标签命中次数**；定义分母与多选规则。
4. 产出清晰的故事线：资料来源 → 分类判据 → 一级分类规模 → 一级/二级/三级 → 设备和机制分布 → 典型案例 → 场景机会 → 设计语言。
5. 先复用原 Figma 的底图、Logo、母版、字号、图表和成熟 SVG 库。用户已有模板时**不要从零画一套相似但不同的设计**。

## 核心画面语言

- **信息多，视觉少**：大标题、充足页边距、清楚网格、单块白色数据板、数据图与行分隔。不要一排排透明卡。
- 在既有项目中，沿用深色原始星空底图＋蓝白＋已有 D&I 角标；换项目时必须换品牌素材，别将星空当通用默认。
- 参考小红书策略提案的是**编辑式留白、内容分组、图表多样性和推理顺序**；不是荧光绿、堆叠胶囊或复制第三方原始素材。
- 用数字粗细/尺寸、标题层级、统一条形长短和实际空白来拉开“一级→二级→三级”，避免所有信息等权。
- 中文主要使用既有文件字体（例如 Noto Sans SC），英文一致使用既定系统（例如 Inter）；现成颜色值优先于主观猜测。
- 1920×1080 常用；章节标题约 52–64px，主类 28–36px，正文 24–30px，数据表 20–24px，**最低字号不得小于18px**。不要缩成一页“显得复杂”。
- 规范正圆（w=h）、圆环同心、细分线可见且粗细统一；不用临时手绘 SVG 或随意拉伸图标。
- 所有页面要保持 Figma 原生可编辑：TEXT、RECTANGLE、ELLIPSE、规范 SVG、分层命名，不拿整页截图蒙混。

## 图表语义（硬性规则）

- 互斥一级类别的比例：圆环或堆叠条，必须满足 `Σn=N`。主图旁边**列出类别名、数量、占比、可展开的二三级信息**，总览不能只有一个大环。
- **多选标签**：不能画总和100%的饼。每个标签用独立出现率 `n(tag)/N(该一级类)` 圆环/条；多个比例**不能相加**。
- 类别内设备构成：**每个一级类一张全量横向条形图**，设备名 → 条形 → 数量 → 真实代表产品。别把可用的长尾隐藏为“其他”。
- 五类×五轴：看“现有编码覆盖”时可用简洁表格＋嵌入比例条；用户明确否决热力图后**不得重做热力图**。未标注≠没有这种特征。
- 一级/二级/三级层级：词表与真实已编码案例明确区分。三级词条可排列成五列索引、分层树或环状分支，形状需精确、字号可读。
- 20案例→机会空间必须有**案例编号—共同机制—目标人群—场景—机会点**的可追溯映射。

详读 [图表选型](references/chart-selection.md)。

## 写作尺度

标题说一个真实问题或判断；数据解释写**谁、何时、做什么、如何回应、结果与风险**。不写“多维赋能、深度转译、高密度系统性综合框架”等套话。用“一个产品可以有多个标签，因此比例不能相加”代替元术语。见 [文案与叙事](references/storytelling-and-copy.md)。

## 开源与工具

首选**已有 Figma 组件**；其次是 Apache ECharts、D3、Observable Plot、Vega-Lite 等可靠图表库，以及 Lucide、Tabler Icons、Heroicons 等一致的 SVG 图标库。使用前核实许可证及实际尺寸。图像用于代表产品和情境，精确数字只能由数据驱动的可编辑元素绘制。

## 最终必须通过

- [ ] 每页统计单位、分母、互斥/多选、缺失值与真实数据相符
- [ ] 总览有一级、二级、三级可理解的入口，后续能找到真实产品例子
- [ ] 无虚构案例、虚构数据、无来源“最优”判断
- [ ] 背景和 Logo 保持已审批版本，色彩与排版在整个系列一致
- [ ] 文字 >=18px，线条清楚，真圆、对齐、无溢出与文字碰撞
- [ ] 没有玻璃拟态/荧光渐变/无用说明文本，不把信息放在过多容器里
- [ ] 没有覆盖既有页；全部新增页可编辑、命名清楚、无重叠
- [ ] 截图走查、数据核验、节点链接齐全；未检查的项目明确标注为未检查
