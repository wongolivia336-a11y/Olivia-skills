# 研究故事线与非 AI 腔文案

## 汇报逻辑

`数据来源与去重口径 → 一级类别与分类依据 → 二级统一分析轴 → 三级细分词条 → 设备／产品分布 → 高频副类 → 典型案例 → 设计机会场景 → 体验蓝图与设计语言`

读者要回答四个问题：**有多少、怎么分、哪些差异、由此能做什么**。每页一条主判断，数据图是证据，不为炫技而变形。

一种经验证的16页分析序列（按真实资料裁剪）：
1. 互斥五类总体圆环＋全部数值。
2. 一级/二级/三级五列框架，整体粗中有细。
3. 五维标注覆盖与缺失，**不把缺失当0**。
4. 五类的主设备对比页。
5–9. 五类各自独立的全量设备条形图。
10. 高频副类的五类对照。
11–15. 五类各自的高频副类独立圆环。
16. 典型产品及其原案例编号索引，承接后续详细案例卡。

## 文案替换

| 不要写 | 建议写 |
| --- | --- |
| 本页通过丰富多维图表实现高密度策略洞察 | 删除，让图表自己说话 |
| 多源生命感关系赋能机制 | 它做了什么，让人觉得被回应？ |
| 结构性生成高价值机会空间 | 这些案例共同留下了什么设计机会？ |
| 通过五维分析实现系统框架转译 | 每个案例都从对象、触发、场景、体验、风险五方面看 |
| 三个高频标签呈现非互斥的共性特征 | 一个产品可同时有多个标签，三个比例不能相加 |
| 无标签表明相关感受缺乏 | 还有一部分案例尚未完成标注 |

写“主体—动作—结果—风险”，区分：事实／对事实的研究解释／未验证假设／设计机会。不要把“觉得被看见”当作统计证明，除非有受访者数据。

## 案例卡

每个产品的主要字段：标准产品名；原案例编号（多个编号保留）；最高原评分或明确的评分算法；主要一级类、辅助一级类；五个二级轴与各自的三级证据；用户群体；交互触发；行为反馈；感受与价值；风险及成立条件；来源链接；缺失字段标注。

## 从20案例到机会场景

一张溯源表：`设计场景ID / 用户与活动 / 触发 / 当前问题 / 涉及案例编号 / 共同机制 / 体验证据 / 设计机会 / 风险／未知`。先找到真实关联，再给场景起自然易懂的名字。不能用照片替代逻辑推导。
