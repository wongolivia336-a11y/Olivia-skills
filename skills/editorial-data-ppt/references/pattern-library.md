# Pattern Library｜经迭代认可的编辑式信息图

这些是可迁移的布局语法，不是第三方方案的图片授权，也不是全项目强制统一的背景。先从已批准的Figma母版获取色票、原背景、字体和角标，再套用下面的信息组织。

## A｜左右双卡大数字开篇

适合两类资料库的规模/构成；上部一个强标题，主体两张并排卡，卡顶有克制的同系蓝色标题带，卡身白底；大数字与单位、简短解释、来源注释分层。不照抄营销参考中的“每日新增、增长”等与研究无关文案。若第二库数量是差额推算，明确写“派生/待核”。

## B｜2×5 载体与典型案例图像矩阵

适合完整展示10种载体。每个格子必须一一对应**真实类别**；上方/图片内显示类别，下方短行展示2–3个可证的典型品牌或案例，不把设备照片错误挪用成其他品类。授权原案例图优先；缺图可以用通用“概念示意”，但需要标注。背景星空不代替图片真伪。

## C｜蓝白渐隐纵向柱形（约7–11个类别）

可用于类别频次、品牌关联案例数、设备构成。主统计白底板，柱形上方同时标实际n和n/N，柱高按真实数量缩放；底部类别清楚可读，避免太长的单行。渐变仅用于**顶部实色、底部渐隐**并保持单一蓝色家族；这种被验证过的渐变是合法例外，不等于允许荧光霓虹。附加重叠生态项用第二色、垂直分隔线和“非加和”解释，不能与互斥十类直接求和。

## D｜单一级类别的全量横条

四列：设备/载体 → 水平数据条 → 真实n → 代表案例/作品。薄行分割比10多张小玻璃卡更专业。长尾项目有原始数据时就展示，不要悄悄归为“其他”。不同页面应统一横条标尺定义。

## E｜总饼/环与内容相关的外展

总览有固定的颜色、扇区起始角、顺序、份额；详情页按当前文字所讲的类别外展**该扇区**，不是每页随机外展同一块。不可为了“复杂感”把二三级标签平均切成假扇区；仅在分层关系和真实数值足够时制作Sunburst。多选标签更适合彼此独立的n/N环或数据条，而不是互斥100%饼。

## 共有的视觉系统

- 有节奏的编辑式留白，而不是容器堆砌；先保证数据层级与对齐。
- 正文一般24–30px，表格建议20–26px，正式答辩文字原则上不小于18px；1920×1080同系列保持一致。
- 正圆锁w=h、同心弧锁中心、线条投影可见；用可靠的Lucide/Tabler/Heroicons库并检查许可证，不手绘不规范SVG。
- 复用批准的背景与Logo，蓝白主色为当前项目特定语言，不能当全部未来项目的永久默认值。
- 数据层为可编辑TEXT/RECTANGLE/VECTOR/ELLIPSE。不能只导入整个参考图截图充当完成。
