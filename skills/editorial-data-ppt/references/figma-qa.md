# Figma 制作与两轮 QA

## 施工前

1. 检查用户原 Figma 的样式：真实背景 image fill、品牌角标、字体、字号、外边距、白色底板、蓝色编码。
2. 明确用户锁定项与可修改项。严格复刻时原文原布局；增量任务严禁覆盖旧页。
3. 列已有可靠母版和案例卡节点，优先克隆经过批准的原生画板；不要每次从零写一套近似 UI。
4. 为所有新增画板统一前缀、顺序和画布尺寸；记录旧画板ID，防止误删。

## 交付层级

- 可编辑 TEXT、RECTANGLE、ELLIPSE、VECTOR，数值和中文都应能直接修改。
- 数字驱动条形宽度、圆环弧长；除法要根据正确分母。
- 真实背景可以是原始已授权图片，整张数据图不可以是截图。
- 真圆宽高相等；描边清楚；一个家族统一网格、字重、表格行高。
- 版权许可可用的图表与图标：ECharts／D3／Observable Plot，Lucide／Tabler Icons／Heroicons。不要上传不明版权的第三方营销方案原图片。

## 检查一：数据

逐项检查合并后产品数量、原案例编号是否全部保留、主类与辅助类是否区分、各设备分组是否加总、n/N是否同口径、未标注是否明确、典型产品是否真正源自库。记录 `Verified / Likely / Hypothesis / Not Tested`。

## 检查二：视觉

每页截图，检查中文换行、标题、列宽、基线、图标来源、圆、内外环半径、颜色、最细线、最小字、底图与右上角标识、卡片阴影、超出画布、页序、画板互相覆盖。最低字号18px，投影阅读优先20–30px。只提供结构检查不能声称已经完成视觉审查。

## 交付日志

```md
版本｜来源节点｜新建节点ID｜修改节点ID｜原画板是否保留
核算：观察单位／去重规则／每页分母／多选／缺失
走查：每页截图验证状态 PASS / FAIL / NOT TESTED
修正项：位置／字号／遮挡／圆形／统计错误
```

用户只要求微调时，修复问题，不重新设计所有页面。若不能写入 Figma 或 GitHub，明确说明未完成，不声称已推送。
