# Field notes｜成功经验、失败反例与回归检查

来自多轮Figma研究汇报真实反馈的**匿名化**沉淀。公共仓库只保存方法和通用例子，不传播客户数据库、第三方提案原件或未经授权的图像。

## 被证明有效的做法

1. **先复刻信息结构，再转译品牌视觉。** 参考的精髓是阅读路径、内容层级、数字和图表的关系，不是它的绿色/紫色。固定的深色背景和蓝白系统可以容纳非常丰富的图表，视觉不会失联。
2. **信息多，但主容器少。** 大面积白色统计板+弱分隔线+高信息条形，替代一排排半透明圆角卡。
3. **可控的蓝色渐隐条。** 数值决定高度、蓝色表达主系列，渐隐只是柔化视觉；真正的特殊统计才有区分色。
4. **内容相关的扇区外展。** 总图扇区的颜色/份额/顺序不变，通过外展当前相关的片段帮助观众映射，不是重新拼一个看起来漂亮的图。
5. **案例图像要对应具体分类。** 载体类别、照片内容、代表品牌必须有事实对应；概念示意与实拍案例的证据级别必须不同。
6. **变更权限优先于Agent审美。** 用户说“只改数字”“不覆盖”“1:1”时，克隆或原地精确补丁，能避免多人手工精修成果被重置。
7. **实际渲染截图是最后的真相。** 节点API成功不代表字幕没有遮挡、中文换行正确、圆仍是真圆。

## 反面教材 → 可检验修复

| 反面 | 造成的错误 | 强制修复 |
|---|---|---|
| 原始案例数、去重产品数、标签归属次数混写 | 统计不一致 | 每页定义观测单位和N，源表追溯 |
| 10种互斥设备外又加一根生态归属柱直接合计 | 多计算案例 | 第二色+隔断+交叉说明，不改变N |
| 新数字已换、扇区角度没改 | 假比例图 | 几何与数值双校验 |
| 总图和详情图的环色/扇区比例漂移 | 无法追踪哪个类别 | 共享色表、起始角、份额，只变高亮位移 |
| 没有历史数据就照搬“上升1位” | 伪造增长 | 删除趋势，替换为真实数量与分母 |
| 把其他设备的照片当当前设备实拍 | 误导 | 匹配类别；缺图时明确概念示意 |
| 胶囊、玻璃卡、霓虹配色过多 | AI味、信息变弱 | 降低容器数量；保留数据、删除装饰 |
| 自绘SVG太细、椭圆、图标系统不一致 | 投影不专业 | 统一线宽，正圆锁比例，优先成熟库 |
| 表格缩到看不清 | 高信息量假象 | 拆成总览/明细页，不降到18px以下 |
| 修改已批准Frame的图形，用户只要求内容更新 | 破坏精修成果 | 锁定可修改节点，严格按diff执行 |
| 未看截图就宣称已经完成 | 字被截、间距拥挤 | 渲染校验并只修问题位置 |
| 用自动推算差额宣称某分库已逐条核实 | 数据过度肯定 | 标记派生与待核，保留源证据 |

## QA回归提示

每次施工结束，独立Agent检查：数据来源和分母是否混了？类别是否互斥？重叠统计是否非加和？条形/扇形几何与真实数量一致吗？颜色是否与前后页同一映射？原有Frame是否被覆盖？照片是真实案例还是示意？有没有未授权的图表改动？是否每页已有实际截图？未验证的项请报告NOT TESTED，不用“整体优秀”代替证据。
