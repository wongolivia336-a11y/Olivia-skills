# Data contract｜案例库统计口径与证据防线

目标：在制作任何研究可视化前先冻结统计对象、分母、版本和多选规则。本文件是通用方法，具体数值应从用户当次最新源文件提取。

## 六种不能混用的单位

| 单位 | 代表什么 | 典型问题 |
|---|---|---|
| N_cases | 原始案例记录，按原编号核对 | 全量分布有多少案例 |
| N_products | 去重后的独立产品 | 一产品对应多少原始案例 |
| N_assignments | 一级类别归属次数 | 多选时总归属可超过案例数 |
| N_tag(class,tag) | 某一级类内打上具体标签的不同案例数 | 其出现率分母应为该类案例数 |
| N_overlay | 与主类有交叉的生态/来源/内部项目 | 不能计为互斥的新增设备类别 |
| N_combined | 两库或多库的项目总和 | 必须检验重复与差额是否只属推算 |

**数据版本优先于PPT既有数字。** 每次都保存：源文件名、Sheet、更新时间、原案例ID、设备类、主/辅助一级类、二级分析维度、三级标签、缺失状态、去重键、品牌别名证据。没有完成读取就不能称“已按最新库更新”。

## 工作前交一份数据字典

source: 最新文件 / sheet / 版本（必须真读到）  
observation_unit: 原始案例 | 独立产品 | 归属次数 | 标签命中  
primary_device: 是否互斥、包括的类别、未分类如何处理  
first_category: 主类是否互斥、辅助标签是否多选  
five_axes: 感知对象/载体；触发/生成机制；场景/时间性；体验/效价；约束/风险  
tertiary_tags: 可多选吗；是否有未标注值  
special_overlay: 哪些生态/来源字段与主设备类交叉  
denominator: 当前图每个百分比的明确N  
evidence_state: Verified | Likely | Hypothesis | Not Tested

## 数学验收

- 互斥设备分组：所有设备类数量求和 = N_cases；未知归类须单列。
- 多选一级标签：归属总次数可能大于独立案例数，标注“归属次数”而不是“产品数”。若部分案例无归属，统计出未分类数量，不能简单要求归属数 ≥ N_cases。
- 独立三级标签：出现率 = 带标签的不同案例数 / 当前一级类不同案例数。多标签比例**不可相加为100%**。
- 特殊生态标签：N_overlay 不增加设备类的整体N；单独用差异色与分隔符，并标“附加项；与前述类别交叉”。
- 条形高度：height_i = availableHeight × n_i / max(n)。如果另标百分比：share_i = n_i / N_cases。柱高比例与占全量比例语义不同，不能混称。
- 饼/环/旭日：必须用真实份额确定弧角；高亮应在**总图同色、同起点、同角度**基础上只改变偏移量。不能数值更新而几何仍是旧比例。
- 从项目总计减去已知分库数得到的剩余，只是**推算差额**。除非单独查验另一分库，不能说已验证其案例完整性。

## 品牌统计

品牌的“识别条数”不等于品牌市场份额，也不等于受访者偏好。必须有品牌别名表、产品系列映射、原编号证据，注明是否一个案例可能涉及多个品牌。没有可信的去重品牌清单，不得把“约70+品牌”一类口头估算作为精准结论。缺乏时间对比就不画“提升1位/每日新增”。
